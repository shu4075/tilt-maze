# みんなで傾ける転がし迷路

会場にいる全員が自分のスマホで「傾けたい方向」を選び、人数が多い方向に床が傾いて、スクリーン上のボールをゴールまで転がす迷路ゲームです。

| 画面 | URL | 使う人 |
| --- | --- | --- |
| メイン画面 | `/host/` | 発表者のPC（プロジェクターに映す） |
| スマホ画面 | `/play/` | 観客（QRコードから開く。アプリは不要） |

| 役割 | 技術 |
| --- | --- |
| サーバー | Node.js + Express + Socket.IO（記録の保存に SQLite） |
| メイン画面 | Three.js（3D表示）+ cannon-es（物理エンジン） |
| スマホ画面 | HTML・CSS・JavaScript（ライブラリなし） |
| QRコード | qrcode（npm） |

## 起動方法

Node.js 20.12 以降が必要です。

```bash
cd tilt-maze
npm install
npm start
```

Windows の PowerShell で「スクリプトの実行が無効」と出るときは、`npm` の代わりに `npm.cmd` と打ちます（`npm.cmd install`、`npm.cmd start`）。

1. PC のブラウザで <http://localhost:3000/host/> を開く（QRコードとルームコードが出る）
2. ステージを選んで「スタート」

### 1台のPCだけで試す

メイン画面とは別のタブで <http://localhost:3000/play/> を開き、画面に出ている4文字のルームコードとニックネームを入れると、スマホの代わりになります。
タブをいくつも開くと別々の参加者として数えられるので、「3人で2対1」などを1台で試せます（同じブラウザの別タブでOK）。

メイン画面のキー操作：

| キー | 動き |
| --- | --- |
| 矢印キー | 床を傾ける（スマホなしで動きを確かめる用） |
| D | デバッグ表示（fps・傾きの受信間隔・押している人数） |
| M | 効果音と BGM のオン／オフ |

## 公開方法

iPhone の傾きセンサーには HTTPS が必要で、会場の Wi-Fi は端末どうしの通信を止めていることが多いので、発表ではインターネットに公開して使います。観客は自分のモバイル回線でも参加できます。

### 方法1：Render に公開する（発表の本番向け）

1. このフォルダ（`tilt-maze`）を GitHub のリポジトリにする（`node_modules` と `data/*.db` は `.gitignore` で除外済み）
2. <https://render.com> にログインし、「New」→「Web Service」でそのリポジトリを選ぶ
3. 設定は `render.yaml` のとおり（Build: `npm install`、Start: `npm start`、プランは Free）
4. できた `https://○○○.onrender.com/host/` を PC で開く。QRコードも自動でそのURLになる

注意：

- 無料プランは、しばらくアクセスがないとサーバーが眠り、最初のアクセスに時間がかかります。**発表の数分前に一度開いて起こしておきます**
- 無料プランではファイルが保存されないので、ランキングの記録は再起動のたびに消えます
- 無料プランの条件は変わることがあるので、使う前に Render のサイトで確かめてください

### 方法2：自分のPCをトンネルで公開する（練習向け・予備）

PC でサーバーを動かしたまま、別のターミナルで次を実行します。

```bash
cloudflared tunnel --url http://localhost:3000
```

表示された `https://○○○.trycloudflare.com` に `/host/` を付けて PC で開きます。URL は起動するたびに変わります。
cloudflared は `winget install --id Cloudflare.cloudflared` で入ります。

## 遊び方と仕様

1. スクリーンのQRコードをスマホで読み、ニックネームを入れて「参加する」
2. 発表者が「スタート」を押すと、3・2・1 のカウントダウン
3. スマホの十字ボタンを**押している間だけ**、その方向に1票（斜めもOK）
4. 床は押している人が多い方向に傾き、ボールが転がる。右と左が同じ人数なら水平に戻る
5. ゴールするか、制限時間（90秒）が過ぎると結果画面へ

床の傾き：

```
θx = θmax × (右の人数 − 左の人数) ÷ 集計に入っている人数
θy = θmax × (手前の人数 − 奥の人数) ÷ 集計に入っている人数
```

| 項目 | 仕様 |
| --- | --- |
| 入力 | 十字ボタン（標準）。スマホを傾ける操作はおまけモード |
| 最大傾き θmax | 15度 |
| 放置した人 | 5秒以上ボタンを押していない人は集計から外す |
| 制限時間 | 1ステージ90秒 |
| 落とし穴 | 落ちたらスタートに戻る |
| 不正対策 | 1人1票。サーバーは「今の向き」を上書きするだけなので、連打しても票は増えない |
| 通信 | スマホは向きが変わったときと1秒ごとに送る。サーバーは集計値を1秒10回まとめて送る |

スマホ画面では、自分の方向が黄色の矢印、今の多数派の方向が緑の三角で出ます。

### おまけ・追加機能

- **傾けて操作（おまけ）**：スマホ画面の「傾けて操作」を押すと、スマホを傾けて入力できます。iPhone は押したときに許可を聞かれます（HTTPS が必要）
- **傾き方式**：待機画面で「平均（標準）／多数決／ランダムに1人」を選べます
- **ランキングと落下ヒートマップ**：クリアタイムと、ボールが落ちた場所を記録して見られます
- **表彰**：結果画面で、いちばん多数派にいた人と、最後まで逆らった人を表彰します
- **リプレイ**：結果画面から、直前のプレイを2倍速で見直せます
- **動く床**：ステージ4はベルトコンベアがボールを押し流します

## 数値の調整

数値はすべてプロジェクト直下の **`config.js` 1か所** にまとめてあります（サーバーとメイン画面の両方がこのファイルを読みます）。

| 定数 | 意味 | 今の値 |
| --- | --- | --- |
| `MAX_TILT_DEG` | 最大傾き | 15度 |
| `TIME_LIMIT_MS` | 制限時間 | 90秒 |
| `IDLE_TIMEOUT_MS` | 放置とみなす時間 | 5秒 |
| `TICK_HZ` | 集計を送る回数 | 1秒10回 |
| `TILT_SMOOTHING` | 傾きのなめらかさ | 0.12 |
| `GRAVITY` / `BALL_DAMPING` / `BOUNCE` | ボールの加速・ブレーキ・跳ね返り | 10 / 0.6 / 0.4 |
| `USE_CHECKPOINTS` | true にすると、落ちたときチェックポイントから再開 | false |
| `MAX_PLAYERS` | 参加人数の上限 | 150 |

変えたあとはサーバーを起動し直し、メイン画面を再読み込みします。

## 負荷テスト（疑似プレイヤー）

スマホを集めなくても、スクリプトで大人数を再現できます。ルームコードはメイン画面のものを使います。

```bash
node tools/bots.js --room ABCD --count 100 --mode random
```

| モード | 動き |
| --- | --- |
| `random` | 1〜4秒ごとにランダムな向き |
| `bias-right` | 7割が右、3割がランダム |
| `split` | 半分が右、半分が左（床は水平のまま） |
| `flaky` | 切断と再接続をくり返す |
| `right` `left` `up` `down` | ずっと同じ向き |
| `neutral` | 何も押さない（5秒で集計から外れる） |

公開したサーバーにつなぐときは `--url https://○○○.onrender.com` を付けます。
メイン画面で D キーを押し、傾きの受信間隔が約100ms（1秒10回）、fps が50〜60なら大丈夫です。

## 発表当日の手順

1. 発表の数分前に、公開したURLの `/host/` を開いてサーバーを起こす
2. プロジェクターに映し、全画面表示（F11）にする
3. 自分のスマホでQRから参加して、動くことを確かめる
4. 観客にQRを読んでもらう → 人数が増えたら「スタート」
5. 結果画面の「次のステージ」「もう一回」で続ける

| 困ったとき | 対処 |
| --- | --- |
| スマホがつながらない | https のURLで開いているか確認。会場Wi-Fiではなくモバイル回線で試してもらう |
| 意見が割れて動かない | 仕様どおり（盛り上がりどころ）。「せーの」で声をかける |
| 傾ける操作が動かない | 「ボタンで操作」に戻す |
| メイン画面を閉じてしまった | 60秒以内に開き直せば同じ部屋に戻る |
| デモが動かない | 矢印キーとボットで見せる。リハーサルの録画も用意しておく |

## ファイル構成

```
tilt-maze/
├── config.js          ★ 数値の設定（ここだけ触れば調整できる）
├── server/
│   ├── index.js       サーバー本体（通信・ゲームの進行・API）
│   ├── config.js      PCごとに変わる設定（ポート番号など。.env で変える）
│   ├── room.js        部屋と参加者の管理（接続切れ・放置の判定）
│   ├── aggregator.js  票の集計と傾きの計算
│   ├── db.js / schema.sql  記録の保存（SQLite）
│   └── seed.js        ステージの検証と読み込み
├── stages/            ステージ（stage1〜4.json）
├── public/host/       メイン画面
│   ├── host.js        画面の切り替えと通信
│   ├── physics.js     ボールの物理（cannon-es）
│   ├── render.js      3D表示（Three.js）
│   ├── minimap.js     床の模様とヒートマップ（2D）
│   └── sound.js       効果音とBGM
├── public/play/       スマホ画面（play.js）
├── tools/bots.js      疑似プレイヤー
└── render.yaml        Render 公開用の設定
```

## ステージの作り方

`stages/` に JSON を置くと、起動時に読み込まれます（横16 × 縦12 マス）。

| 記号 | 意味 |
| --- | --- |
| `#` | 壁 |
| `.` | 床 |
| `S` / `G` | スタート / ゴール（1つずつ） |
| `H` | 落とし穴 |
| `<` `>` `^` `v` | 動く床 |
| `C` | チェックポイント（`USE_CHECKPOINTS` が true のときだけ働く） |

行の長さ、外周の壁、S と G の数、S から G まで穴を通らずに行けるかを起動時に確かめ、だめならエラーで止まります。`node server/seed.js` でも確認できます。
